# Smart Study Planner & Task Management API Documentation

Welcome to the REST API technical reference for the **Smart Study Planner & Task Management System**. This document outlines the API contracts, response envelopes, endpoint specifications, query conventions, enum definitions, and testing resources for the backend service.

---

## 1. Overview & Base URL

The Smart Study Planner backend provides a stateless, RESTful JSON API implemented with **Spring Boot 3** and **Java 21**. All communication uses JSON over HTTP/HTTPS with standard HTTP verbs and status codes.

### Base URLs

| Environment | Base URL | Description |
|---|---|---|
| **Development** | `http://localhost:8080/api` | Local Spring Boot development server |
| **Production** | `/api` (or `https://<domain>/api`) | Production API deployment |
| **Swagger UI** | `http://localhost:8080/swagger-ui.html` | Interactive Swagger API documentation |
| **OpenAPI Spec** | `http://localhost:8080/v3/api-docs` | Raw OpenAPI 3.0 JSON specification |

### Default Headers

| Header | Value | Requirement | Description |
|---|---|---|---|
| `Content-Type` | `application/json` | Required for POST / PUT | Specifies JSON payload format |
| `Accept` | `application/json` | Recommended | Specifies expected response format |

## 2. Authentication & Authorization

> [!NOTE]
> **Version 1 Scope**: The v1 API is unauthenticated and single-tenant by design. All endpoints are publicly accessible without API keys or authorization headers.

### Future Architecture (v2 Roadmap)
In v2, authentication will be introduced using **Spring Security** and **JWT (JSON Web Tokens)**:
- Outbound requests will require the `Authorization: Bearer <jwt_token>` header.
- A `user_id` foreign key will partition tasks per authenticated user.

## 3. Common Response Envelopes

Every API endpoint returns a standardized response envelope for consistency across all clients.

### 3.1 Success Envelope (`ApiResponse<T>`)

All `2xx` successful responses wrap the payload in an `ApiResponse<T>` structure:

```json
{
  "success": true,
  "message": "Operation successful",
  "data": { ... },
  "timestamp": "2026-10-15T18:00:00"
}
```

#### Envelope Fields

| Field | Type | Description |
|---|---|---|
| `success` | `boolean` | Always `true` for successful operations. |
| `message` | `string` | User-friendly confirmation message. |
| `data` | `object` / `array` / `null` | The response payload (`TaskResponse`, `PagedResponse<TaskResponse>`, `DashboardSummaryResponse`, or `null`). |
| `timestamp` | `string (ISO-8601)` | Server timestamp of the response (`YYYY-MM-DDTHH:mm:ss`). |

---

### 3.2 Error Envelope (`ErrorResponse`)

All `4xx` and `5xx` error responses return a structured `ErrorResponse` generated by `GlobalExceptionHandler`:

```json
{
  "success": false,
  "message": "Validation failed for one or more fields",
  "errorCode": "VALIDATION_ERROR",
  "details": [
    "taskName: Task name is required",
    "deadline: Deadline must be in the present or future"
  ],
  "timestamp": "2026-10-15T18:00:00",
  "path": "/api/tasks"
}
```

#### Envelope Fields

| Field | Type | Description |
|---|---|---|
| `success` | `boolean` | Always `false` on errors. |
| `message` | `string` | High-level error summary. |
| `errorCode` | `string` | Machine-readable error code (`VALIDATION_ERROR`, `RESOURCE_NOT_FOUND`, `INVALID_REQUEST`, `INTERNAL_SERVER_ERROR`). |
| `details` | `array of strings` | Granular field-level or system-level error messages. |
| `timestamp` | `string (ISO-8601)` | Server timestamp of the error event. |
| `path` | `string` | The URI path where the error occurred. |

### 4.1 Create Task — `POST /api/tasks`

Creates a new study task with Jakarta Bean Validation.

#### Request Body (`TaskCreateRequest`)

| Field | Type | Required | Constraints | Description |
|---|---|---|---|---|
| `taskName` | `string` | **Yes** | `@NotBlank`, max 150 chars | Name/title of the task |
| `subject` | `string` | **Yes** | `@NotBlank`, max 100 chars | Academic subject or category |
| `description` | `string` | No | `@Size(max=2000)` | Detailed description / notes |
| `priority` | `string` | **Yes** | `@NotNull`, enum (`HIGH`, `MEDIUM`, `LOW`) | Priority level |
| `deadline` | `string` | **Yes** | `@NotNull`, `@FutureOrPresent`, ISO-8601 | Due date & time (`YYYY-MM-DDTHH:mm:ss`) |
| `status` | `string` | No | enum (`PENDING`, `IN_PROGRESS`, `COMPLETED`) | Defaults to `PENDING` if omitted |

#### Sample Request

```http
POST /api/tasks HTTP/1.1
Host: localhost:8080
Content-Type: application/json

{
  "taskName": "Complete Operating Systems Lab",
  "subject": "Computer Science",
  "description": "Implement multi-threaded CPU scheduler simulation in C++",
  "priority": "HIGH",
  "deadline": "2026-10-20T23:59:00",
  "status": "PENDING"
}
```

#### Sample Response (`201 Created`)

```json
{
  "success": true,
  "message": "Task created successfully",
  "data": {
    "id": 1,
    "taskName": "Complete Operating Systems Lab",
    "subject": "Computer Science",
    "description": "Implement multi-threaded CPU scheduler simulation in C++",
    "priority": "HIGH",
    "deadline": "2026-10-20T23:59:00",
    "status": "PENDING",
    "createdAt": "2026-10-01T10:15:30",
    "updatedAt": "2026-10-01T10:15:30"
  },
  "timestamp": "2026-10-01T10:15:30"
}
```

#### Error Responses
- **`400 Bad Request`**: Validation failure (missing required fields, deadline in past, text exceeding length).
  ```json
  {
    "success": false,
    "message": "Validation failed for one or more fields",
    "errorCode": "VALIDATION_ERROR",
    "details": ["taskName: Task name is required"],
    "timestamp": "2026-10-01T10:15:30",
    "path": "/api/tasks"
  }
  ```

### 4.8 Dashboard Summary — `GET /api/dashboard/summary`

Computes aggregated metrics and the top 5 upcoming deadlines for the dashboard view.

#### Query Parameters
None.

#### Sample Request

```http
GET /api/dashboard/summary HTTP/1.1
Host: localhost:8080
Accept: application/json
```

#### Sample Response (`200 OK`)

```json
{
  "success": true,
  "message": "Dashboard summary retrieved successfully",
  "data": {
    "totalTasks": 8,
    "completedTasks": 3,
    "pendingTasks": 3,
    "inProgressTasks": 2,
    "completionPercentage": 37.5,
    "upcomingDeadlines": [
      {
        "id": 1,
        "taskName": "Complete Operating Systems Lab (Revised)",
        "subject": "Computer Science",
        "description": "Implement multi-threaded CPU scheduler and priority queue in C++",
        "priority": "HIGH",
        "deadline": "2026-10-22T18:00:00",
        "status": "IN_PROGRESS",
        "createdAt": "2026-10-01T10:15:30",
        "updatedAt": "2026-10-01T11:45:00"
      }
    ]
  },
  "timestamp": "2026-10-01T12:15:00"
}
```

#### Aggregate Metric Descriptions

| Field | Type | Description |
|---|---|---|
| `totalTasks` | `long` | Total count of all tasks in the database. |
| `completedTasks` | `long` | Count of tasks with status `COMPLETED`. |
| `pendingTasks` | `long` | Count of tasks with status `PENDING`. |
| `inProgressTasks` | `long` | Count of tasks with status `IN_PROGRESS`. |
| `completionPercentage` | `double` | `(completedTasks / totalTasks) * 100`, rounded to 2 decimal places (0.0 if totalTasks == 0). |
| `upcomingDeadlines` | `array` | Top 5 nearest pending/in-progress tasks sorted by `deadline ASC` where `deadline >= now()`. |

## 5. Enum Reference

### 5.1 Priority Enum

Stored as `VARCHAR`/`ENUM` in MySQL and mapped to Java `Priority` enum:

| Enum Value | Label | Semantic Meaning | Recommended UI Color |
|---|---|---|---|
| `HIGH` | High Priority | Critical or urgent task requiring immediate focus | `error` (Red / `#d32f2f`) |
| `MEDIUM` | Medium Priority | Normal priority task | `warning` (Orange / `#ed6c02`) |
| `LOW` | Low Priority | Low urgency or discretionary task | `success` (Green / `#2e7d32`) |

### 5.2 Status Enum

Stored as `VARCHAR`/`ENUM` in MySQL and mapped to Java `Status` enum:

| Enum Value | Label | Semantic Meaning | Recommended UI Color |
|---|---|---|---|
| `PENDING` | Pending | Task is created but not yet started | `default` (Gray / `#757575`) |
| `IN_PROGRESS` | In Progress | Task is actively being worked on | `info` (Blue / `#0288d1`) |
| `COMPLETED` | Completed | Task has been successfully finished | `success` (Green / `#2e7d32`) |

## 6. Pagination & Sorting Conventions

1. **0-based Page Indexing**: The first page is `page=0`.
2. **Page Size (`size`)**: Default is `10`. Minimum is `1`.
3. **Sort Fields (`sortBy`)**:
   - `createdAt` (default for general listing)
   - `deadline` (used for deadline sorting)
   - `taskName`, `subject`, `priority`, `status`
4. **Sort Directions (`sortDirection`)**:
   - `desc` (default)
   - `asc`
5. **Paged Response Structure (`PagedResponse<T>`)**:
   - `content`: Array of elements for the current page slice.
   - `page`: Current page number (0-indexed).
   - `size`: Page size limit.
   - `totalElements`: Total number of records across all pages.
   - `totalPages`: Total number of available pages.
   - `last`: Boolean indicating if this is the final page.
